# SMS UI Build Progress

Tracking implementation of the full school-ERP feature spec on top of the existing React 19 + TS + Vite + shadcn/Radix + TanStack Query + zustand stack. UI-only — every module fakes a backend via localStorage + mockDelay, same convention as the original 7 modules (students, staff, administration, authentication, dashboard, parent-portal).

## Done (14 of 18 tracked modules) — built, type-checked, linted, and manually verified in-browser

1. **Academic Management** (`src/features/academics/`) — Academic Years, Terms, Departments, Classes, Sections, Subjects, Class Capacity, Merge Sections, Academic Calendar. Route: `/academics`.
2. **Attendance Management** (`src/features/attendance/`) — student/staff daily marking, capture-mode selector (manual + simulated QR/RFID/biometric/face/mobile), Daily/Monthly/Yearly reports. Route: `/attendance`.
3. **Teacher Management** (`src/features/teachers/`) — thin layer over `staff`: teacher list, subject/class-teacher assignment, lesson plans, student performance view. Routes: `/teachers`, `/teachers/:staffId`.
4. **Timetable Management** (`src/features/timetable/`) — weekly period grid per section, manual + naive auto-scheduler, rooms, teacher-view/student-view, substitute-teacher assignment. Route: `/timetable`.
5. **Examination Management** (`src/features/examinations/`) — exam types/schedules, bulk marks entry, grade/GPA/CGPA/ranking, report cards, transcripts. Route: `/examinations`.
6. **Homework & Assignment + lightweight LMS** (`src/features/homework/`) — homework CRUD/grading, student submit/resubmit, learning resources (video/notes/pdf/ppt), quizzes with auto-scoring, discussions, progress overview. Routes: `/homework` (staff), `/my-homework` (student/parent).
7. **Fee Management** (`src/features/fees/`) — fee structures, discounts/scholarships, late fines, installments, invoice generation, payment recording, receipts, refunds. Route: `/fees`. Rewired `parent-portal`'s Fees tab to read/pay through this module instead of its old standalone mock.
8. **Library Management** (`src/features/library/`) — books (with barcode/QR), authors/publishers/categories, members (students+staff), issue/return with fines, reservations. Route: `/library`.
9. **Transport Management** (`src/features/transport/`) — buses, drivers (thin layer over `staff` designation "Driver", same convention as `teachers`), routes with ordered stops (add/edit/reorder/delete), student-to-route/stop assignment, simulated GPS live-tracking per bus (idle → on-route → at-stop → completed state machine, manually advanced). Route: `/transport`.
10. **Hostel Management** (`src/features/hostel/`) — hostels (with warden, thin layer over new `staff` designation "Warden"), rooms with bed capacity (no separate bed entities — occupancy derived from active allocations, same pattern as Library's book copies), student room/bed allocation, visitor register (check-in/out), hostel attendance (reuses `attendance`'s `StatusToggleGroup`), monthly hostel fee tracking (generate-for-month + mark-paid), per-hostel weekly mess menu grid (7 days × 4 meals, click-to-edit). Route: `/hostel`.
11. **Communication Center** (`src/features/communication/`) — compose/broadcast across channels (email/SMS/push/WhatsApp/in-app as multi-select tags via a new `ChannelSelector`, simulated per-channel delivery with a configurable success rate), reusable templates, recipient groups (audience type students/staff/parents, built over the real students/staff directories), individual recipient picking via a reusable `MultiSelectList`, optional scheduling (`datetime-local`) with send-now/cancel on pending scheduled messages, delivery-summary detail view. Route: `/communication`.
12. **Notification Center & unified Calendar** — two features, one number:
    - **Notification Center** (`src/features/notifications/`) — a real, persisted notification inbox (not dashboard's old static mock): read/unread (shared per record — there's no multi-user backend here, just one active demo session at a time), role-scoped or global visibility, admin/principal-only "Post announcement" composer, a header bell (`NotificationBell`, new — Header had no notification affordance before) with live unread badge, and a full `/notifications` page. **Communication Center's "in-app" channel now actually lands here**: `communication/api.ts`'s `composeMessage`/`sendScheduledNow` call a new `postFromCommunication()` in the notifications module whenever "in-app" is one of the chosen channels, as a global (not per-recipient) notification — arbitrary student/staff ids in a message's recipient list don't map to the handful of demo `AuthUser` accounts, so exact per-person targeting isn't possible here; broadcasting globally was the honest choice over fabricating fake per-user delivery.
    - **Calendar** (`src/features/calendar/`) — a read-only `/calendar` page aggregating holidays/exams/term dates/events (academics' `CalendarEvent`, plus one new seed entry for a PTA meeting), per-subject exam schedules (examinations), homework due dates (homework), staff leave (staff — **not** student/parent leave requests, see follow-ups below), and recurring yearly birthdays (students + staff), each joined against the owning module's real records (subject/class names, staff names) rather than shown as bare ids. Month grid with per-category dot colors, a day-detail panel, and category show/hide checkboxes.
13. **Reports & Analytics dashboards** (`src/features/reports/`) — nine read-only recharts dashboards, all pulling live from existing modules' own `list*`/`get*` APIs with no new persisted data (same convention as the Calendar aggregator): Student Performance (examinations — exam-over-exam trend + latest-exam class averages), Attendance (attendance's own `getYearlyTrend` for students, `listStaffAttendanceRecords` grouped client-side for staff), Fee Collection (fees' invoices, collected-by-payment-date vs. pending-by-due-date), Teacher Performance (`teachers.getTeacherPerformanceOverview` looped per teacher), Admissions (status donut + monthly volume), Dropout Analysis (`Student.status "inactive"` as the dropout bucket, by-class breakdown), Library Usage (loan volume + busiest categories), Transport Utilization (active assignments vs. bus capacity per route), Hostel Occupancy (`hostel.listHostels()`'s already-rolled-up `occupiedCount`/`bedCount`). Charts reuse dashboard's existing PerformanceChart/RevenueChart color language (`--color-brand-500`, `#eef0f3` grid, `#94a3b8` ticks) rather than introducing a new palette. Route: `/reports`, gated by a new `reports` permission (off for parent/student, on for everyone else — this module surfaces school-internal data, unlike Transport/Hostel/Communication which stayed open to parents).
14. **Settings & Administration** (`src/features/settings/`) — School Profile (name/address/contact/principal + a "current academic year" switch that calls academics' own `updateAcademicYear`), **Branding** (a real, live re-theme: 5 accent-color presets swap all 9 `--color-brand-*` shades plus `--color-primary`/`--color-ring`/`--color-accent*`/`--color-sidebar-accent*` on `document.documentElement` at runtime, applied synchronously at module load in `App.tsx` before first paint so a saved preset never flashes default — see `settings/theme.ts`), Localization (language/timezone/currency/date-format, saved as a preference — deliberately **not** wired to reformat the many existing `formatCurrency("en-IN"/"INR")` call sites across the app, to avoid a risky blanket behavior change for a "nice to have"), system Templates (email/SMS bodies for system-triggered messages — welcome/password-reset/fee-receipt/admission — distinct from Communication Center's ad-hoc broadcast templates), Backup & Restore (real JSON export of every `sms-mock-*`/`sms-settings-*` localStorage key via Blob+download, restore from a file, and a "reset demo data" that wipes operational module data back to reseed-fresh while deliberately preserving Settings' own profile/branding/audit trail), and a real Audit Log that Settings' own mutations write to (not retrofitted into the 13 other modules — see follow-ups). Route: `/admin/settings`, nested under the existing Administration nav section alongside User Management and Roles & Permissions.

Shared files extended along the way (additive only): `src/app/router.tsx`, `src/app/App.tsx` (module-scope `applyBrandPreset` bootstrap call), `src/constants/nav.ts`, `src/types/auth.ts` (`ModulePermissions`), `src/features/authentication/mockUsers.ts` (`FULL_PERMISSIONS`), `src/features/staff/types.ts` + `constants.ts` (`StaffDesignation` gained "Warden", alongside the pre-existing "Driver"), `src/components/layouts/Header.tsx` (new `NotificationBell`), `src/features/academics/mock.ts` (one new PTA `CalendarEvent`).

## Known follow-ups worth a look
- One background build hit a session/usage limit mid-task (Fee Management) and left a dangling broken edit in `parent-portal/api.ts` — it was caught and fixed by hand before moving on, with a full live-browser re-verification (invoice list, payment flow, receipt creation all confirmed working). Worth double-checking any *future* interrupted module the same way before trusting its "done" report.
- `Student.className`/`section` are plain strings, not id-linked to the Academic Management module's `Section.id`. Attendance/Teachers/Examinations/Homework all work around this today by string-matching. A future cleanup could migrate `Student` to hold a real `sectionId`.
- Caught during Transport: `z.coerce.number().optional()` on a zod form field does NOT stay `undefined` when the input is left blank — `Number("")` is `0`, a valid number, so it silently coerces to `0` instead of skipping. Fixed there with `z.preprocess((v) => (v === "" ? undefined : v), z.coerce.number().optional())`. Worth checking any *other* optional numeric form field (discounts, fines, etc.) for the same silent-zero bug if it comes up again.
- Transport's student assignments are a separate `StudentTransportAssignment` record (studentId/routeId/stopId), intentionally not synced back into the existing free-text `Student.transport.routeName`/`pickupPoint` fields from the students module — kept decoupled to match module-9 scope. Task 16 (dashboard bus-status widget) should read from the new transport module, not the old free-text fields. Hostel followed the same decoupled pattern for `Student.hostel.hostelName`/`roomNumber` vs. the new `HostelAllocation` records.
- Caught during Hostel: deriving a "YYYY-MM" month key via `new Date(year, month, 1).toISOString().slice(0, 7)` is wrong in any positive-UTC-offset timezone (e.g. IST) — local midnight on the 1st converts to the *previous* UTC day, so the key silently rolls back a month (seed data showed a "previous month" fee payment labeled two months back). Fixed with a `monthKey(year, monthIndex0)` helper in `hostel/constants.ts` that formats from local `getFullYear()`/`getMonth()` directly, never through `toISOString()`. `todayDateKey()` in `attendance/constants.ts` (reused elsewhere) has the same latent class of bug for the pre-midnight-IST window, but it's an existing cross-module convention — left alone rather than fixed as a drive-by.
- CSS `text-transform: capitalize` capitalizes *each* hyphen-separated segment, so a raw enum value like `"co-ed"` renders "Co-Ed" instead of "Co-ed". Caught in Hostel's hostel-type display; fixed by rendering the mapped option label instead of relying on `capitalize` for any value that might contain a hyphen.
- The unified Calendar deliberately excludes student/parent leave requests. `parent-portal/api.ts`'s `leaveByStudent` store is lazily seeded per student the first time that student's parent-portal page is opened, with no "list every student's leave requests" API — building one for the calendar would mean generating random demo data for every student in the directory just to render a month view. If a future module adds a real school-wide student-leave list, wire it into `calendar/api.ts`'s `listAggregatedCalendarEvents()` alongside the existing staff-leave source.
- Caught during Notification Center: after `composeMessage`/`sendScheduledNow` post an in-app notification, the header bell and `/notifications` page didn't refresh until a manual reload — react-query had no reason to refetch `["notifications", ...]` since nothing in the communication module's own success handlers invalidated it. Fixed by having `ComposeTab`'s and `HistoryTab`'s mutation `onSuccess` also invalidate `["notifications"]` when the sent message's channels include "in-app". Worth checking for the same stale-cache gap wherever one module's write is meant to show up live in another module's UI.
- Caught during Reports: both the Transport Utilization and Hostel Occupancy reports initially counted *inactive* routes/hostels toward total capacity (e.g. Transport's inactive Route 4, whose bus is under maintenance, added 40 seats nobody could actually use, understating utilization for the routes that are actually running). Fixed by filtering to `status === "active"` before summing in both `getTransportUtilizationReport()` and `getHostelOccupancyReport()` in `reports/api.ts`. Worth checking any *future* report aggregator the same way — a raw sum over a module's full list silently includes retired/inactive records unless explicitly filtered.
- Caught during Settings: an `<Select>` bound to react-hook-form via `Controller`, on a `useForm()` with **no synchronous `defaultValues`**, populated only later by `reset(asyncQueryData)` in a `useEffect` — the field's value silently never renders in the trigger (`SelectValue` stays blank) even though the underlying form state is actually correct (confirmed by opening the dropdown: the right item was highlighted, just not displayed as the trigger's label). Every other `Controller`+`Select` form built this session (Communication, Notifications, Hostel, Transport) was safe because it always seeded `useForm({ defaultValues: emptyValues })` synchronously first; Localization was the one exception, fixed by dropping RHF entirely for that form in favor of plain `useState` synced from the query — the same direct-binding pattern Settings' own Academic Year `<Select>` already used successfully. If a future form needs Select-via-Controller populated from an async source, give `useForm` real `defaultValues` up front rather than leaving fields `undefined` until `reset()` fires.
- Settings' Backup & Restore was verified live only for **export** (real download, correct file size, backup-history + audit-log entries all confirmed in-browser). Restore-from-file and Reset-demo-data were code-reviewed but not exercised end-to-end — both trigger `window.location.reload()`, and Restore additionally needs picking a real file through the OS's native file dialog, which browser automation can't drive. Worth a manual click-through before relying on either in a demo.
